## 2. Independent verification performed

1. **Read `core/orchestrator.py`'s re-plan loop directly** (lines 331–354). The emission is inside `while planner_result.status == PlannerStatus.IMPASSE:`, guarded by `if not budget.consume():` (line 332) — i.e. it fires only when `OperationRecoveryBudget.consume()` returns `False`. Read `consume()` itself (`core/cognitive/recovery.py` lines 66–78): it returns `False` exactly when `exhausted` (`internal_recovery_used >= max_total_recovery_attempts`), `True` otherwise while incrementing the counter. So the emission is exhaustion-gated by construction, not a per-impasse event — confirmed from the primitive's own implementation, not inferred from a name.
2. **Read `tests/test_orchestrator_recovery.py::TestTerminalImpasseEvent` directly** (lines 226–272). `test_terminal_impasse_event_emitted_on_exhaustion` sets `max_recovery_attempts=1`, mocks `plan()` to return `IMPASSE` unconditionally, and asserts against the real captured `event_stream.append` call args: exactly one `cognitive.planner_impasse_terminal` call, with `trace_id` truthy, `operation_id`, `goal_id`, and all three `recovery_budget_state` sub-fields checked against expected values. This genuinely drives the exhaustion path and inspects the real emitted payload — it is not a test that merely asserts its own mock. `test_terminal_impasse_event_not_emitted_on_success` mocks a successful replan on the 2nd `plan()` call and asserts `terminal_calls == []`, directly confirming exhaustion-only firing from the negative side.
3. **Compared the payload against the canonical spec.** Three different field lists exist across the same document and needed reconciling, not just one:
   - The authoritative "Diagnostic Events" contract table (§7, line 402): `trace_id`, `operation_id`, `goal_id`, `impasse_detail`, `recovery_budget_state` — 5 keys.
   - An older illustrative code sketch elsewhere in the same document (§ "[MODIFY] core/orchestrator.py", lines ~583–590, predating the "[CORRECTED]" pass applied to the table above it): `interaction_id`, `impasse_detail`, `recovery_budget_remaining` (flat, not structured) — 3 keys, inconsistent with both the table and the actual code.
   - The actual implementation (`core/orchestrator.py` lines 334–348): `trace_id`, `operation_id`, `interaction_id`, `goal_id`, `impasse_detail`, `recovery_budget_state` (structured: `max_total_recovery_attempts`, `internal_recovery_used`, `remaining`) — 6 keys.

   Judgment: the §7 table, not the superseded illustrative snippet, is the authoritative "payload keys" contract — it is the document's dedicated contract table for exactly this purpose, while the snippet is a pre-correction worked example inside a "MODIFY" instructions section. Against the table, the implementation is a strict superset (all 5 required keys present, plus `interaction_id` for finer correlation). "Full payload" per H2-G3 is satisfied.

## 3. Findings

- **Single emission site, no duplication risk.** Repo-wide search confirms `cognitive.planner_impasse_terminal` is emitted from exactly one call site (`core/orchestrator.py:334`); `core/cognitive/planner.py:227` only documents in a docstring that its `operation_id` is meant for the caller's reuse in this event, it does not emit it. The emitting branch `return`s immediately after the `await self._emit_event(...)` call, so the same operation cannot fire it twice.
- **Deterministic precheck rejection cannot reach this path, by construction.** The `while` loop's condition is `status == PlannerStatus.IMPASSE`; `PlannerStatus.REJECTED_PRECHECK` never satisfies it, so the loop body containing the emit call is never entered for that status — this is a structural guarantee, confirmed by direct reading of the control flow, not an inference from test behavior. The existing test `test_rejected_precheck_is_not_retried_and_consumes_no_budget` (lines 204–221) confirms the causally sufficient precondition (`plan()` called exactly once, i.e. the loop body never executes) but does not itself add a direct assertion that `cognitive.planner_impasse_terminal` is absent from `event_stream.append.call_args_list` in that specific scenario. Noted as a minor test-coverage completeness gap, not a correctness gap — the control-flow guarantee is independent of test assertions.
- **DRIFT-07 whitelist matches exactly.** `scripts/check_drift.py`'s `DRIFT_07_EXCEPTIONS` contains precisely one entry: `("core/orchestrator.py", "cognitive.planner_impasse_terminal")`. Running `scripts/check_drift.py` against the branch as received: **9/9 PASS**, including DRIFT-07, with its own note citing `core/orchestrator.py:333` — matching the documented D10 baseline in `docs/architecture/h2_packets/README.md`.
- **No per-attempt (non-terminal) impasse event exists anywhere in the codebase** (`grep -rn "impasse_attempt"` across all `.py` files: zero matches). Explicitly out of this packet's scope per the brief; confirmed absent rather than assumed absent.

## 4. Conclusion

H2-G3 is satisfied by the existing H1 implementation. No production code change required or made. `core/orchestrator.py` was read only, never written, consistent with this packet's ownership scope.
